# Known Limitations and Scope Boundaries (Phase 2 Update)

## 1. Scope Boundary: OCR-Free Vector Extraction

`document-ingestion-benchmark` focuses strictly on **deterministic, OCR-free vector text and geometric extraction**.

- **Capabilities**: Full extraction of digital PDFs generated by word processors, LaTeX, enterprise ERP systems, and programmatic report generators with standard text layers.
- **Limitation**: Scanned raster bitmap documents (photocopied paper, faxed PDFs without OCR text layers) are not processed by the Phase 1/Phase 2 parser. If an image-only PDF is passed, the parser emits a diagnostic warning: `Converted markdown is empty`.

---

## 2. Multi-Column Complex Layouts

- **Current Heuristic**: The line clusterer sorts words primarily by vertical coordinate (`top`), followed by horizontal offset (`x0`).
- **Limitation**: In newspapers or multi-column academic papers where two columns of text sit side-by-side on the same vertical level, reading across columns sequentially (interleaving column 1 and column 2) can occur if explicit column separation boundaries are not provided.
- **Mitigation**: Standard single-column and block-oriented enterprise layouts are handled with high fidelity. Multi-column spatial partitioners (Voronoi/XY-cut) are scheduled for future iterations.

---

## 3. Metric-Specific Limitations Identified During Phase 2 Validation

Through adversarial corruption testing, the following evaluation boundary limitations were identified and documented:

### 3.1 Intra-Paragraph Word Scrambling vs. Reading Order
- **Observation**: `reading_order` tracks ordered landmark anchors (e.g. section titles, first sentences of key paragraphs). If words are scrambled *within* a single paragraph while the landmark anchor phrase remains in position, `reading_order` continues to register the anchor as in-sequence.
- **Countermeasure**: This condition is caught by `text_completeness` via `SequenceMatcher` ratio and `Token F1`, which severely penalize scrambled words.

### 3.2 Anchor Substring Collisions
- **Observation**: `reading_order` uses `lower_md.find(anchor.lower())`. If a short anchor phrase appears multiple times in a document, `find()` matches the first occurrence.
- **Countermeasure**: Ground-truth manifests must select unique, landmark phrases for reading order anchors.

### 3.3 Table Row Transposition with Identical Content
- **Observation**: If two rows within a table possess identical text values in every column and their positions are swapped, coordinate-based cell accuracy evaluates both as matching.
- **Impact**: In practice, enterprise tables rarely have identical duplicate rows; semantic row identity is preserved.

---

## 4. Complex Tabular Merges (Colspan / Rowspan)

- **Current Behavior**: Tables are extracted as 2D rectangular matrices of dimension $R \times C$.
- **Limitation**: Complex enterprise tables containing multi-level grouped headers with horizontal span (`colspan > 1`) or vertical cell spans (`rowspan > 1`) are flattened into discrete cell slots.
- **Handling**: In standard GitHub Flavored Markdown (GFM), HTML `colspan` is unsupported; cells are padded to preserve uniform column alignment across rows.

---

## 5. Non-Rectangular / Borderless Tables

- **Current Engine**: `pdfplumber.find_tables()` relies on explicit line vectors and rectangular bounding borders.
- **Limitation**: Borderless whitespace-only tables (where columns are separated solely by horizontal tab gaps) may occasionally be interpreted as regular text lines rather than structured Markdown tables.
- **Mitigation**: Diagnostic warnings are logged when ambiguous column gutters are encountered.
